# Fraud Detection Script

A menu-driven Python command-line tool that loads a transactions CSV, cleans it, summarises it in detail, and draws charts of fraud patterns.

## Features

- **Load** – reads the CSV and checks the required columns exist before accepting the data
- **Clean** – parses timestamps and amounts, normalises the `Is Fraud` column, flags problem rows as `INVALID` (rows are never deleted), and reports duplicates
- **Summarise** – runs every summary in one go: overall totals, time patterns, amounts, merchants and locations
- **Visualise** – six charts, saved as PNG files, with a sub-menu to pick one or run all
- **Safe by design** – the original CSV is never modified; cleaning only affects data in memory

## Requirements

- Python 3 (developed and tested on 3.14.2)
- [pandas](https://pandas.pydata.org/)
- [matplotlib](https://matplotlib.org/)

## Usage

Place the script and the CSV in the same folder, then run:

```bash
python victor_fraud_detection.py
```

On Mac/Linux you may need `python3`.

The menu starts with no data loaded, so choose **1** first:

| Option | Action |
|--------|--------|
| 1 | Load the fraud detection data |
| 2 | Clean the fraud detection data |
| 3 | Summarise the fraud detection data (all summaries at once) |
| 4 | Visualise the data (opens a chart sub-menu) |
| 5 | Exit |

Options 2–4 show *"No data loaded"* until option 1 succeeds. If a chart window cannot open (e.g. headless environments), the PNG is still saved.

## Summaries (option 3)

| Section | What it shows |
|---------|---------------|
| Overall | INVALID vs OK rows, total money lost to fraud, fraud as a % of transaction count and of total value |
| Time | Earliest and latest dates; fraud by month, year, day of week and hour |
| Amount | Mean, median, min and max for fraud vs legitimate; fraud rate by amount band; top 5 largest transactions; outliers (more than 3 standard deviations above the mean) |
| Merchant | Busiest merchants, most fraud, highest fraud rate (2+ transactions), total fraud value per merchant |
| Location | Locations with the most fraud, fraud rate per location (min 2 transactions) |

Merchant and location sections only run if the CSV has a matching column; otherwise they are skipped with a message.

> With a small dataset (~100 rows), merchant and location groups can be tiny. A high rate on 1–2 transactions is weak evidence, so look at count and rate together.

## Charts (option 4)

| Choice | Chart | Saved as |
|--------|-------|----------|
| 1 | Fraud vs non-fraud counts (bar) | `fraud_counts_chart.png` |
| 2 | Fraud by month (bar) | `fraud_by_month_chart.png` |
| 3 | Histogram of amounts | `amount_histogram.png` |
| 4 | Box plot: amount by fraud status | `amount_boxplot_fraud.png` |
| 5 | Fraud by merchant (bar) | `fraud_by_merchant_chart.png` |
| 6 | Fraud by location (bar) | `fraud_by_location_chart.png` |
| 7 | Run all charts | all of the above |
| 8 | Back to main menu | – |

Charts 5 and 6 only work if the matching column exists in the CSV.

## Input Data Format

The CSV must contain these columns:

| Column | Expected values |
|--------|-----------------|
| `Timestamp` | Any date/time format pandas can parse |
| `Amount (USD)` | Numeric |
| `Is Fraud` | `True`/`False`, `1`/`0`, `yes`/`no`, `y`/`n` (case-insensitive) |

Optional columns, detected automatically if present:

| Data | Accepted column names |
|------|-----------------------|
| Merchant | `Merchant`, `merchant`, `Merchant Name`, `merchant_name` |
| Location | `Location`, `location`, `City`, `city`, `Transaction City`, `transaction_city` |

To use a different file, change this line near the top of the script:

```python
file_name = "your_file.csv"
```

## How Cleaning Works

| Issue | Handling |
|-------|----------|
| Unparseable timestamps | Converted to `NaT` |
| Non-numeric amounts | Converted to `NaN` |
| Zero or negative amounts | Flagged as invalid |
| Unrecognised `Is Fraud` labels | Converted to missing |
| Any of the above | Row marked `INVALID` in a new `Data Status` column (otherwise `OK`) |
| Duplicate rows | Counted and reported, not removed, since repeats may be genuine |

## Design Notes

- The interactive menu is the only entry point.
- Each step is its own function (`load_data`, `clean_data`, the `summary_*` and `chart_*` functions), so steps can be repeated.
- Bad rows are marked rather than dropped so they can be reviewed.
- Counts and rates are shown together so risk isn't judged on counts alone.
- Missing `pandas`/`matplotlib` produces a clear install message instead of a traceback.
